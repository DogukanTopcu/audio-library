## Quick Reference Guide - Audio Library Implementation

### 🚀 Quick Start

```bash
# 1. Setup database
cd packages/db
npm run db:migrate    # Apply migrations (0000, 0001)
npm run db:seed       # Seed sample data

# 2. Start API
cd ../apps/api
npm run start:dev

# 3. Login to get token
curl -X POST http://localhost:3000/auth/login \
  -d '{"email":"kullanici@ozanbayir.com","password":"Kullanici123!"}'
```

### 📚 All API Endpoints at a Glance

| Feature | Method | Endpoint | Auth | Purpose |
|---------|--------|----------|------|---------|
| **CONTENT DISCOVERY** | | | | |
| List books | GET | `/content` | No | Kesfet page - browse all books |
| Get book details | GET | `/content/:id` | No | View single book |
| Get chapters (with progress) | GET | `/content/:id/chapters` | Yes | Show hierarchy with completion % |
| Get chapters (public) | GET | `/content/:id/chapters-public` | No | Public chapter view |
| **AUDIO PLAYER** | | | | |
| Get audio token | GET | `/player/token?audioRecordId=...` | Yes | Get signed URL for playback |
| Update progress | PATCH | `/player/progress` | Yes | Track position & completion |
| Get all progress | GET | `/player/progress` | Yes | View all listening history |
| Get last chapter | GET | `/player/progress/last-chapter` | Yes | Continue from where you left |
| Get chapter progress | GET | `/player/progress/chapter/:id` | Yes | Chapter completion stats |
| **QUESTION BANK** | | | | |
| Get chapter questions | GET | `/questions/chapter/:id` | Yes | Get all Qs for chapter |
| Get single question | GET | `/questions/:id` | Yes | Get Q with choices |
| Submit answer | POST | `/questions/:id/answer` | Yes | Answer a question |
| Get chapter Q stats | GET | `/questions/progress/chapter/:id` | Yes | Success rate per chapter |
| Get incorrect Qs | GET | `/questions/progress/incorrect` | Yes | For retry panel |
| **PROGRESS DASHBOARD** | | | | |
| Overall stats | GET | `/ilerleme` | Yes | Dashboard stats |
| Per-content progress | GET | `/ilerleme/contents` | Yes | Progress per book |
| Chapter breakdown | GET | `/ilerleme/contents/:id/chapters` | Yes | Chapter-level details |
| Retry questions | GET | `/ilerleme/retry-questions` | Yes | Incorrect questions |
| Statistics | GET | `/ilerleme/statistics` | Yes | Detailed analytics |

### 💾 Database Schema

**New Table: user_question_answers**
```
id (UUID, PK)
user_id (FK → users)
question_id (FK → questions)
selected_choice_index (int) - which choice user selected
is_correct (bool) - correct/incorrect
attempt_count (int) - number of attempts
time_spent_seconds (int) - time to answer
metadata (JSONB) - extra data
answered_at (timestamp)
created_at (timestamp)
```

**Related Tables**
- users - User profiles
- questions - Question records
- question_choices - Answer options
- audio_records - Audio files
- chapters - Chapter structure
- content - Books/textbooks
- user_progress - Listening progress
- user_activity_logs - Activity tracking

### 🛠️ Troubleshooting

**Port already in use**
```bash
# Use different port
npm run start:dev -- --port 3001
```

**Database migration fails**
```bash
# Check migrations directory
ls packages/db/migrations/

# Run specific migration
npm run db:migrate
```

**Seed fails - user already exists**
```bash
# Safe to re-run - seed checks for existing records
npm run db:seed
```

**Token expired**
```bash
# Get new token
curl -X POST http://localhost:3000/auth/login \
  -d '{"email":"kullanici@ozanbayir.com","password":"Kullanici123!"}'
```

### ⚡ Performance Tips

1. **Pagination** - Use limit/offset for large datasets
   ```bash
   GET /ilerleme/retry-questions?limit=10&offset=0
   ```

2. **Caching** - Frontend can cache content (rarely changes)
   ```bash
   GET /content  # Cache for 1 hour
   ```

3. **Progress Updates** - Batch updates to reduce database hits
   - Update position every 30 seconds
   - Update completion status once

4. **Query Optimization** - All queries optimized to avoid N+1

### 🔄 User Journey Example

```
1. User opens app
   → GET /content (list books)

2. User clicks "Matematik 9"
   → GET /content/{id}/chapters (show chapters with %)

3. User clicks "Chapter 1: Temel Sayılar"
   → GET /player/token (get audio URL)
   → Audio player loads and plays

4. User finishes listening
   → PATCH /player/progress (mark completed)

5. User wants to practice questions
   → GET /questions/chapter/{id} (show all questions)
   → User answers questions
   → POST /questions/{id}/answer (submit answer)

6. User views progress
   → GET /ilerleme (show dashboard)
   → GET /ilerleme/retry-questions (show incorrect Qs)

7. User reattempts incorrect question
   → POST /questions/{id}/answer (submit new answer)
   → If correct, success page
   → If incorrect, offer explanation audio
```
